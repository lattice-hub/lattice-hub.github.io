---
title: 控制台使用
description: Console 在服务治理、配置、规则发布和权限管理中的使用边界。
---

Console 是平台团队操作 Lattice Hub 的主入口。它不应被理解成独立系统，而是控制面资源的可视化管理层。

## 主要任务

| 任务 | 说明 |
| --- | --- |
| 服务管理 | 按运行环境查看服务、实例、主动健康检查和运行状态。 |
| 配置管理 | 创建配置、发布版本、灰度、回滚并监听变更。 |
| 治理工作台 | 管理路由、泳道、限流、熔断、故障探测、无损上下线、镜像、Mock 和调用鉴权。 |
| 权限管理 | 维护用户、角色、策略和资源访问边界。 |
| AI 工具 | 管理 MCP Server、A2A Agent Card、技能和后端服务绑定。 |
| Pole Agent | 通过白名单工具读取资源，并在人工确认后准备配置草稿。 |
| 系统配置 | 查看 63 项类型化配置目录、来源、apply mode、草稿与发布状态。 |
| 平台监控 | 查询 OTel 指标、Collector 和共享 GreptimeDB 提供的控制面概览。 |

## 使用原则

- 管理态编辑和运行态发布分开处理。
- 治理规则发布前先确认资源存在性和权限点。
- 对配置和治理规则保留灰度、回滚和历史记录。
- 平台级操作优先通过 Console 完成，业务运行时通过 SDK、Controller 或 Pole Sidecar 消费结果。
- Pole Agent 的配置修改确认后只保存草稿，发布仍由用户进入配置中心完成。
- 系统配置不是全部热更新；部署锁定和待重启字段会明确展示其生效方式。
