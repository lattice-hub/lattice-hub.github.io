## 配置分组

路径：`/configuration/group`。

1. 用命名空间、发布状态（「待发布」/「无待发布」）和名称搜索定位分组。
2. 「新建配置分组」：命名空间、分组名、描述、部门、业务、标签。
3. 列表可看文件数、加密数、待发布标记（「有变更」/「无」）。
4. 操作：查看文件、**授权**、删除。  
   - 分组下仍有文件时不能删，提示「请先删除 N 个配置文件」。

## 配置文件

进入分组后打开具体文件：

| 按钮 / Tab | 作用 |
| --- | --- |
| 编辑 / 保存草稿 | 改正文后保存为正式草稿（编辑态） |
| 撤销 | 放弃未保存修改 |
| 发布配置 | 打开发布向导 |
| 交给 Agent | 跳到 Agent 工作台并带上该文件上下文 |
| 授权 | 对该文件做资源授权 |
| Tab「文件内容」 | 编辑或只读预览 |
| Tab「基本信息」 | 描述、是否加密、算法、文件标签 |
| Tab「发布记录」 | 四态发布记录（见下） |
| Tab「订阅查询」 | 查看订阅客户端及灰度命中情况 |

约束：单文件内容最大 20,000 字符；列表分页最大 100。

状态常见文案：编辑待发布、灰度发布中、发布成功、发布失败、未发布。

## 发布配置（两步）

点「发布配置」打开抽屉「发布配置」：

1. **版本对比** → 下一步  
2. **发布信息**
   - 版本名称（必填，≤64；重名会提示将重新发布）
   - 发布说明（≤255）
   - 发布类型：
     - **全量发布**：替换当前全量基线。提示原文：「全量发布会替换当前全量基线，不结束正在生效的灰度版本。」
     - **灰度发布**：需至少一条灰度规则；可设灰度优先级（1–9999，默认 100）。客户端需**同时满足全部**灰度规则（AND）。

确认后点「确认发布」。

## 发布记录四态（必须理解）

在文件「发布记录」Tab：

| Tab | 含义 |
| --- | --- |
| 正式发布 | 当前全量基线；正式发布**不会**结束 active 灰度 |
| 灰度发布 | 可有多条 active 灰度独立生效 |
| 正式草稿 | 由灰度转正或手工编辑生成，**尚未**影响线上客户端 |
| 历史记录 | 已归档、回滚生成或删除后的记录 |

### 常见操作

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 停灰度 | 灰度中版本 →「删除灰度」 | 命中客户端回落当前全量；toast「停止灰度成功」 |
| 灰度转正准备 | 灰度中 →「提交为正式草稿」 | 生成正式草稿，再对其「发布正式草稿」做全量 |
| 回滚 | 历史/非当前版本 →「回滚至此版本」 | 生成新的当前全量；**不会**自动停止 active 灰度 |
| 删除当前全量 | 删除确认 | 未命中灰度的客户端可能拿不到配置，需谨慎 |

## 与 Pole Agent 的衔接

Agent 确认后的写操作**只保存草稿**。你仍须回到本页执行「发布配置」。见 [Pole Agent 工作台](/docs/guides/console/agent)。
