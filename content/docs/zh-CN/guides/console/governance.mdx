对应菜单：**治理管理 → 治理工作台**（`/governance/workbench`）。也可从服务详情「流量治理」Tab 嵌入进入。

![治理工作台](/images/console/governance.png)

## 工作台列表

页头「规则治理工作台」。

1. 查看摘要：规则总数 / 已启用 / 待发布 / 规则类型数。
2. 筛选：归属环境、规则类型、状态（全部/已启用/已停用）、搜索规则名/服务/条件。
3. 「新建规则」打开类型向导，选择九类之一：
   - 路由、限流、熔断、探测、无损、泳道、鉴权、镜像、Mock
4. 列表操作：进入详情、删除等（受权限与 `editable`/`deleteable` 标记约束）。
5. 需要时对规则做**资源授权**。

服务内嵌工作台可切换「作为主调方」/「作为被调方」，并「关联规则」。

## 规则详情三个 Tab

![治理规则详情](/images/console/governance-detail.png)

| Tab | 用途 |
| --- | --- |
| 规则 | 编辑规则本体并保存 |
| 版本 | 查看发布版本、回滚、删除版本 |
| 监听 | 查看客户端监听情况（创建中规则时可能禁用） |

创建流程中，版本/监听 Tab 可能处于不可用状态，需先完成规则创建。

## 发布规则

在详情中点「发布」，打开抽屉「规则发布」：

1. 确认规则 ID / 名称。
2. 填写版本名称（必填 ≤64）、版本描述（≤255）。
3. 选择发布策略：
   - **全量发布**：面向全部客户端；文案强调确认无风险后的正式发布。
   - **灰度发布**：只对命中**客户端标签**条件的请求生效；至少 1 个标签条件，key 不可重复。
4. 灰度标签可含：客户端 IP / 客户端 ID / 客户端语言；匹配类型含完全匹配、正则、包含、范围等。
5. 点「发布」。

与配置中心不同：治理侧灰度条件是「满足**任一**标签条件即命中」（OR），不是配置灰度的 AND 规则组。

## 版本操作

在「版本」Tab：

- 状态：「使用中」/「历史」；类型：全量 / 灰度。
- **回滚**：对非当前、非灰度限制下的历史版本执行「回滚至此版本」。
- **删除**：删除使用中版本会导致客户端拿不到该规则，需确认。

治理发布记录**没有**配置中心那套「正式草稿 / 提交为正式草稿 / 删除灰度」四 Tab，不要混用两套语义。

## 泳道特殊边界

泳道编辑器对**启用状态**的保存文案是：「启用状态 - 保存后立即下发到数据面」，成功 toast「已保存并下发到数据面」。

这意味着泳道的启用开关与「点发布才生效」的通用模型不同。操作启用状态前要当作会立即影响数据面；版本化发布仍走「发布」按钮。若文档与现场行为不一致，以页面提示为准。

## 发布前检查清单

- [ ] Namespace / 作用服务正确
- [ ] 具备对应 Publish 权限（如 `PublishRouteRules`）
- [ ] 灰度标签可解释、可收回
- [ ] 回滚目标版本仍在列表中
- [ ] 需要时已做资源授权

## 九类观察点

| 类型 | 发布后重点观察 |
| --- | --- |
| 路由 / 泳道 | 流量是否落到预期实例或泳道 |
| 限流 | 拒绝是否符合阈值 |
| 熔断 / 探测 | 打开与恢复是否符合条件 |
| 无损 | 上线延迟与摘流是否平滑 |
| 鉴权 | 拒绝是否准确 |
| 镜像 / Mock | 副作用是否限制在目标范围 |
