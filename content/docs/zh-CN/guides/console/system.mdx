对应菜单：**系统配置**（`/system-configuration`）。仅 `main` / `admin` 可访问；其他角色会被挡回命名空间页。

![系统配置](/images/console/system-config.png)

## 页面结构

1. 顶部切换组件：`Pole Server` / `Console`。
2. 左侧/列表按领域浏览，例如：启动与装配、命名空间、服务发现、配置中心、缓存同步、存储、认证授权、工作负载凭证、日志、运行时、上游连接、可观测查询、Agent 等。
3. 可用搜索与来源过滤定位配置项。
4. 列展示：配置项、当前有效值、来源、发布目标、**生效方式**、管理方式（页面可编辑 / 部署配置）。

## 生效方式（apply mode）

| UI 文案 | 含义 |
| --- | --- |
| 仅启动配置 | `BootstrapOnly`：只能改部署/启动配置 |
| 重启生效 | `RestartRequired`：可发布期望值，实例标记待重启 |
| 动态生效 | `HotReload`：具备安全 applier 时可热更新 |
| 受控动态生效 | `GuardedHotReload`：带额外护栏的热更新 |

页面提示大意：自举、Secret 和部署拓扑字段保持锁定；重启级配置发布后会明确标记为待重启。

## 可编辑配置的操作流

对允许页面管理的字段：

1. 修改生成**草稿**。
2. **审阅** desired（发布目标）与 effective（当前有效）差异。
3. **发布**期望值。
4. 观察是否已热更新，或显示「待重启」。

不要把「已发布期望值」理解成「所有实例已生效」。

## Agent 域

在 Agent 相关配置领域可：

- 编辑模型 / Gateway / MCP 等字段
- 做连接测试
- 发布后，部分项会提示已热更新到当前实例

API key 等敏感项为 write-only Secret：页面、diff、日志与模型上下文只看到引用，不回显明文。

## 与监控的关系

系统配置管的是控制面自身参数；运行态看板在 [监控指标](/docs/guides/console/metrics)。没有观测栈时监控页可能无数据，不等于系统配置失败。
