Pole Sidecar 是 Lattice Hub 的轻量数据面方向，当前基于 Pingora 实现。它使用 TOML 配置，支持 HTTP 与 gRPC 转发，并保留治理拦截器扩展点。事实来源仍是控制面的服务发现与 active 治理视图。

![sidecar data plane](/diagrams/sidecar-data-plane.svg)

## 当前能力

- 入站：HTTP/1.1 与 HTTP/2，支持 gRPC-h2c。
- 出站：按 HTTP 路由前缀或 gRPC 前缀选择上游集群。
- 负载均衡：简单轮询。
- 拦截器骨架：请求阶段与上游阶段的回调占位，可扩展 ACL、限流、熔断和指标。

## 快速开始

```bash
cargo build
RUST_LOG=info cargo run
SIDECAR_CONFIG=./sidecar.toml RUST_LOG=debug cargo run
```

Rust 工具链要求：`1.74+`。

## 配置要点

- 路由匹配顺序：先匹配 `grpc_prefix`，再匹配 `prefix`。
- gRPC 识别：HTTP/2 且 `content-type` 以 `application/grpc` 开头。
- `clusters[].endpoints` 定义上游；`lb_policy` 当前示例为 `round_robin`。
- 可选独立 `inbound_grpc` 端口；也可以与 HTTP 共用 `8080`。

## 与控制面的关系

- Sidecar 不重新定义服务治理事实。
- 生产路径应消费控制面 active 配置，而不是长期手写死 endpoints。
- 可与 Kubernetes Controller 的注入模式（`dns` / `mesh`）配合。

## 后续演进

访问控制、限流、熔断、动态路由和 Prometheus 指标暴露是明确的扩展方向；接入前先在实践页完成路由与发现闭环。
