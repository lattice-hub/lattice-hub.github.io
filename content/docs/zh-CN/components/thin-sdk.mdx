---
title: Thin SDK
description: Go、Java、Python 与 Node.js 的 Thin SDK 契约核心，按 TargetEnvelope v1 编码本地 Pole Sidecar 目标信封。
---

Thin SDK 是面向 **Pole Sidecar** 的多语言接入层，与 [Rust SDK](/docs/components/rust-sdk) 的 Proxyless 路径不同：应用不直连控制面做完整治理消费，而是构造正式 `TargetEnvelope v1`，交给本地 Sidecar 执行。

## 语言与仓库

| 语言 | 仓库 | 说明 |
| --- | --- | --- |
| Go | [pole-client-go](https://github.com/lattice-hub/pole-client-go) | 标准库实现，Go 1.22+ |
| Java | [pole-client-java](https://github.com/lattice-hub/pole-client-java) | Java 17+，无运行时依赖 |
| Python | [pole-client-python](https://github.com/lattice-hub/pole-client-python) | Python 3.9–3.13，零运行时依赖 |
| Node.js | [pole-client-nodejs](https://github.com/lattice-hub/pole-client-nodejs) | 包名 `@pole-io/pole-client-nodejs` |

契约源在 [specification / thin-sdk](https://github.com/lattice-hub/specification/tree/thin-sdk-contract-v1.0.0/thin-sdk)，正式 tag 为 `thin-sdk-contract-v1.0.0`。各语言仓库的 `contract/` 目录 vendoring 同一份 Schema 与一致性向量。

## 当前能力边界

当前各语言仓库只交付**框架无关的契约核心**：

- 构造、校验 `TargetEnvelope v1`
- 编码为发给本地 Sidecar 的 HTTP Header
- 不绑定 `http.RoundTripper`、gRPC、Dubbo 或其他框架 adapter

Pole Sidecar 尚未完成对应本地专用 listener 的端到端验证，因此**不能宣称 Thin SDK → Sidecar 已生产就绪**。官网与文档只记录契约核心已交付这一事实。

## 与 Rust SDK 的分工

| 路径 | 组件 | 角色 |
| --- | --- | --- |
| Proxyless | [Rust SDK](/docs/components/rust-sdk) | 应用直连控制面发现 / 配置端口，本地执行路由与负载均衡等治理逻辑 |
| Sidecar | Thin SDK + [Pole Sidecar](/docs/components/pingora-sidecar) | 应用编码目标信封；治理与转发由本地数据面承担 |

需要语言无关或旁路代理时优先看 Thin SDK / Sidecar；Rust 服务若希望进程内完整治理，继续使用 Rust SDK。
