服务治理要被 Agent 使用，关键不是再做一套“提示词目录”，而是让 MCP Server、Tool、A2A Agent Card 与 Skill 进入和控制面其他资源相同的生命周期。

## 为什么要进控制面

- 统一 Namespace 运行环境边界。
- 复用 API、store、CacheManager 与权限模型。
- 目录具备 revision，客户端知道何时刷新。
- 变更可进入 History，而不是散落在各 Agent 本地配置。

## MCP 与 A2A 的边界

| 能力 | 做什么 | 不做什么 |
| --- | --- | --- |
| MCP Registry | 登记 Server/Tool，供发现与白名单调用 | 不替代业务后端执行语义 |
| A2A Registry | 登记 Agent Card、技能与协议元数据 | 不负责任务代理或 Runtime |
| Pole Agent | 只读查询 + 人工确认后的配置草稿 | 不自动发布/删除 |

## 实践结论

1. 能力目录只有一份，来源是控制面。
2. Agent 也是鉴权主体，不能绕过策略。
3. 写操作继续遵守“草稿 → 人工发布”。
