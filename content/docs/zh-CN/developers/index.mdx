开发者分区记录项目治理角色与公开名单。当前项目仍处于早期阶段，Maintainer 与 Committer 主要由同一位核心贡献者兼任。

## 角色说明

| 角色 | 职责 |
| --- | --- |
| Maintainer | 负责项目方向、版本节奏、关键变更评审，以及对发布质量与社区规范负责 |
| Committer | 拥有仓库写权限，可审阅并合并符合项目标准的贡献 |

## 当前名单

- [Maintainers](/docs/developers/maintainers)：项目维护者
- [Committers](/docs/developers/committers)：具备提交权限的贡献者

## 如何参与

1. 先读 [术语与概念](/docs/what-is/concepts) 与 [控制面装配架构](/docs/principles/architecture)，对齐事实边界。
2. 通过 Issue 说明问题或提案；改动尽量附可复现步骤。
3. Pull Request 保持小而可审；文档变更与代码事实保持一致，不编造压测数字或默认密码。
4. 贡献被长期认可后，可被提名为 Committer；对架构与发布持续负责的 Committer，可进一步成为 Maintainer。

## 文档贡献提示

- 产品事实以 `product-facts.md` 与控制面实现为准。
- Namespace ≠ 租户；A2A ≠ Runtime；Pole Agent ≠ 自动发布。
- 新增原理图优先放 `public/diagrams/`，中英文页同步引用。
