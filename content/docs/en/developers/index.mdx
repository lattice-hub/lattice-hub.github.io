This section records project governance roles and public membership. The project is early-stage; Maintainer and Committer duties are currently concentrated on the same core contributor.

## Roles

| Role | Responsibility |
| --- | --- |
| Maintainer | Direction, release cadence, critical reviews, quality and community norms |
| Committer | Write access; review and merge contributions that meet project standards |

## How to contribute

1. Read [Concepts](/en/docs/what-is/concepts) and [Control-plane assembly](/en/docs/principles/architecture).
2. Open issues with reproduction steps.
3. Keep PRs small and reviewable; keep docs aligned with code facts—no invented benchmarks or default passwords.
4. Sustained contributors may be nominated as Committers; Committers who own architecture and releases may become Maintainers.

## Docs tips

- Product facts follow `product-facts.md` and control-plane implementation.
- Namespace ≠ tenant; A2A ≠ runtime; Pole Agent ≠ auto-publish.
- Put new diagrams under `public/diagrams/` and reference them from both locales.
