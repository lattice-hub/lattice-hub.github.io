Console is the operator-facing component of Lattice Hub. It can run with the server in `all` mode or as a separate `console` process that reaches the Control Plane over the network.

Step-by-step operations: [Using the Console](/en/docs/guides/console-use).

## Workspaces

- Discovery and configuration resource management.
- Governance scope, rule detail, revisions, releases, progressive delivery, and rollback.
- Identity, users, policies, and authorization diagnostics.
- MCP Registry and A2A Agent Registry management.
- Pole Agent conversations and human-confirmed proposals.
- System settings, Pole Secret rotation, connection testing, and runtime readiness.
- Platform metrics backed by OpenTelemetry and shared GreptimeDB.

## Design system

Console uses Microsoft Fluent UI React v9 with Fluent Web Blue (`#0F6CBD`), cool-gray page background, white surfaces, and shared light/dark semantic tokens. No decorative gradients or glow effects.

## Pole Agent

Pole Agent is a first-class Console workspace. It uses a versioned prompt, an OpenAI-compatible LLM gateway, and allowlisted Pole MCP tools. Configuration updates require preview and human confirmation, then save as drafts only. Publish/rollback/delete stay on deterministic product paths.

Write coverage today is limited to existing configuration-file updates. Governance writes, server-side session persistence, and streaming are still evolving. Without an LLM gateway/API key, `/agent` is unavailable; the rest of Console still works.

## System configuration

Sixty-three typed settings are registered; a subset is page-manageable. Apply modes:

- `BootstrapOnly` — deployment config only
- `RestartRequired` — desired value published, instance reports pending restart
- `HotReload` — controlled hot update where a safe applier exists

Agent API keys use write-only Secrets; pages, diffs, logs, and model context only see SecretReferences.
