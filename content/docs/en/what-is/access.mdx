Integration paths follow where the workload runs. Platform teams usually deploy the Control Plane and Console first, then choose SDK, Kubernetes Controller, or Pole Sidecar.

See [Concepts and terminology](/en/docs/what-is/concepts) for vocabulary boundaries.

## Paths

| Scenario | Start here | Notes |
| --- | --- | --- |
| Platform management | [Using the Console](/en/docs/guides/console) | Services, config, governance, users, and policies. |
| Control-plane deploy | [Server installation](/en/docs/guides/server-install) | Control Plane, MySQL, and bootstrap config. |
| Proxyless clients | [Rust SDK](/en/docs/components/rust-sdk) | Direct discovery/config/governance consumption. |
| Kubernetes clusters | [Kubernetes Controller](/en/docs/components/kubernetes-controller) | Service sync, annotations, injection. |
| Local data plane | [Pole Sidecar](/en/docs/components/pingora-sidecar) | HTTP/gRPC forwarding beside the app. |
| Protocol / gateway | [Specification](/en/docs/components/specification) | Shared contracts and multi-protocol adapters. |

## Port cheat sheet

| Purpose | Default port |
| --- | ---: |
| Console | 8080 |
| HTTP API | 8090 |
| Discovery gRPC | 8091 |
| Config gRPC | 8093 |
| xDS v3 | 15010 |
| Eureka | 8761 |
| Nacos | 8848 |
| Apollo | 8890 |

Compatible protocol ports follow `deploy/conf/pole-apiserver.yaml`; they listen only when the matching entry is enabled.

## Recommended order

1. Read the [product overview](/en/docs) and [features](/en/docs/what-is/features).
2. Deploy the control plane and verify Console plus cache refresh.
3. Pick one runtime path: SDK, Controller, or Sidecar.
4. Put configuration and governance behind progressive delivery and rollback.
